# 投资研究：巴菲特-芒格-段永平-李录 四大师综合分析框架（混合流程版）

对 $ARGUMENTS 进行系统化投资研究分析。

## 角色分工（本 Skill 的执行宪法）

本 Skill 采用 **NotebookLM 为主、主 LLM 为编排器** 的混合流程，目的是把最烧 token 的"读长文本 + 写长文"外包给 NotebookLM，把最讲求数值严谨性的"计算 + 验算 + 准出"留给主 LLM。

| 角色 | 承担 | 工具 |
|------|------|------|
| **NotebookLM** | 长文本注入、高密事实提取、六模块长文生成 | `notebooklm` CLI |
| **主 LLM** | 流程编排、精确计算（`financial_rigor.py`）、数字对账、综合备忘录、准出审核 | Bash 调工具 |
| **硬纪律** | 所有涉及计算的数据必须由主 LLM 通过工具验算，**禁止任何 LLM（含 NotebookLM）心算数字** | — |

> NotebookLM 写出的长文里出现的数字**未经程序验证**，必须经过下方"数字对账"步骤才能采信。这是混合流程不破坏原 Skill 严谨性命门的关键。

---

## 研究框架

基于巴菲特、芒格、段永平、李录四位投资大师的方法论，按以下阶段顺序执行：

```
[偏见自觉] → [数据摄入 1A/1B/1C] → [六模块长文外包 2~7] → [数字对账] → [综合备忘录 8] → [写入文件] → [数据抽检准出]
```

### 前置步骤：AI研究偏见自觉（必须执行）

在开始研究前，先评估该公司的"AI可研究性"，识别潜在的数据偏见。此步可由 NotebookLM 一次性 `ask` 完成结果，主 LLM 只收结论写入报告开头。

**信息丰富度评级**：
| 等级 | 特征 | AI研究陷阱 | 应对策略 |
|------|------|-----------|---------|
| A级（信息充裕） | 上市多年、券商覆盖多、媒体报道密集 | 共识过强，AI输出趋同于市场定价，alpha有限 | 重点做反面检验：聪明人为什么不买？被忽略的风险是什么？ |
| B级（信息适中） | 上市1-3年、覆盖有限、部分数据需推算 | AI可能用"合理推测"填补空白，看起来完整实则虚假确定性 | 每个推算数据标注置信度，区分"有据推算"和"凭空填充" |
| C级（信息稀缺） | 刚上市/冷门股/新兴市场、几乎无覆盖 | AI会因资料不足而过度保守，误判为"看不清=不好" | 用第一性原理提问（见下方），从有限信息中提取商业本质 |

**C级公司的第一性原理研究法**：
当公开资料不足时，不要试图拼凑出"看起来完整"的报告，而是聚焦以下底层问题：
1. 客户是谁？为什么付钱？有没有替代选择？
2. 复购靠什么驱动？是习惯、锁定、还是持续创造新价值？
3. 竞争对手拿100亿能复制这门生意吗？
4. 管理层做过什么关键决策？这些决策反映了什么判断力和价值观？

**偏见自查清单**（研究全程保持警惕）：
- [ ] 我的"确定性"感受是来自生意本质，还是来自资料数量？
- [ ] 如果把这家公司的资料量减少一半，我的结论会变吗？
- [ ] AI输出的分析是否与市场共识高度雷同？如果是，我的信息优势在哪？
- [ ] 是否存在"公开资料很少但生意本质极好"的可能性被低估了？

> 将信息丰富度评级结果写入报告开头，并在最终结论中注明"AI研究置信度"与"实际投资确定性"的区别。

### 第一步：数据摄入与结构化提取

数据源规范：参见 `skills/financial-data.md`。本阶段把长文本拦在 NotebookLM 内，主 LLM 只消费压缩后的结构化结果。

#### 阶段 1A：构建专属知识库（主 LLM 0 Token 消耗）
调用 `notebooklm` CLI，将目标公司的关键长文本资料注入 NotebookLM 笔记本：
- 财报原文 (10-K/10-Q PDF)
- 电话会议纪要 (Earnings Call Transcripts)
- 多源财务数据网页 (Macrotrends, StockAnalysis, 东方财富等)
- 必要时用 `source add-research` 让 NotebookLM 自行做深度网络调研补料

```bash
notebooklm create "{公司名}投研" --json
# 解析 .notebook.id 作为后续所有命令的 -n / --notebook 参数
notebooklm source add "https://macrotrends.net/..." --json
notebooklm source add ./10K.pdf --json
notebooklm source add-research "{公司名} 财报 护城河 管理层 估值" --mode deep --no-wait
notebooklm source wait <source_id>   # 等待处理完成
```

#### 阶段 1B：高密事实提取（逐项 ask，用完即弃）
对下列 10 项，**逐项**调用 `notebooklm ask --json`，主 LLM 只把每项答案压缩成一张事实表的行，**用完即从上下文丢弃原始答案全文**，避免 10 项长驻上下文（这是原流程最大的输入 token 浪费点）：

1. 收入结构：最近财年及近4季度分部收入、增速、毛利率
2. 财务指标：近5年收入、净利润、毛利率、经营利润率、自由现金流、现金储备
3. 竞争格局：市场份额、主要竞争对手对比
4. 商业模式与护城河：核心竞争优势来源（摘录管理层 MD&A 论述）
5. 技术能力：核心技术栈、研发投入
6. 管理层：创始人/CEO履历、持股比例、关键决策记录
7. 行业前景：TAM（总可寻址市场）、增长预测
8. 风险因素：地缘政治、监管、供应链等（摘录 10-K Risk Factors）
9. 当前估值：市值、PE、PS、PEG、EV/Revenue
10. 多空双方核心论点

```bash
notebooklm ask "提取近5年收入/净利润/毛利率/FCF/现金储备，输出 Markdown 表格，标注来源" --json -n <notebook_id>
# 主 LLM 仅保留表格行，丢弃自然语言叙述
```

> 关键纪律：1B 产出的"事实表"是后续所有数字对账的基准。NotebookLM 给出的数字仍可能错，必须经过 1C 与第七步工具验算才能采信。

#### 阶段 1C：数据交叉验证（必须执行，主 LLM 亲自做）
1B 完成后，**主 LLM 必须调用 `tools/financial_rigor.py` 对关键数据进行程序化验证**，杜绝 NotebookLM 与 LLM 的幻觉和心算误差。此阶段不可外包给 NotebookLM。

**必须验证的数据点**：
- 总股本（至少2个源确认）
- 当前股价和市值（**手动计算 股价×总股本 并与报告市值对比，防止单位错误**）
- 最近财年收入和净利润（从公司年报+至少1个第三方源确认）
- 现金储备和净现金（现金+短期投资-总债务，注意口径差异）
- 管理层持股比例（区分经济权益和投票权，注意AB股结构）

**强制验证步骤（主 LLM 用 Bash 调工具）**：

Step 1 — 市值验算（精确十进制，非浮点）：
```bash
python3 tools/financial_rigor.py verify-market-cap \
  --price {股价} --shares {总股本} --reported {报告市值} --currency {币种}
```

Step 2 — 关键数据多源交叉验证：
```bash
python3 tools/financial_rigor.py cross-validate \
  --field {字段名} --values '{"来源1": 数值, "来源2": 数值}' --unit {单位}
```
对收入、净利润、现金储备分别执行。

Step 3 — 估值指标精确验算（PE/PB/ROE/FCF Yield 等）：
```bash
python3 tools/financial_rigor.py verify-valuation \
  --price {股价} --eps {EPS} --bvps {每股净资产} --fcf-per-share {每股FCF} --dividend {每股股息}
```

**验证规则**：
1. 每个关键数据点至少2个独立来源
2. 发现来源间有差异时，优先采用公司年报/交易所数据，并注明差异原因
3. **所有涉及计算的数据必须通过工具验算，禁止LLM心算**（含 NotebookLM）
4. 工具输出结果直接嵌入报告附录"关键数据交叉验证记录"
5. 如果工具报告 ❌ 偏差过大，必须排查 NotebookLM 提取源的错误后才能继续分析。

**常见错误防范**：
- 市值单位：港币亿 vs 人民币亿 vs 美元亿，容易漏写/多写一个零
- FCF口径：不同来源对资本支出的定义可能不同（是否含租赁、收购等）
- 债务口径：是否包含经营租赁负债
- 持股比例：AB股公司的经济权益 ≠ 投票权

### 第二步~第七步：六模块长文生成（外包给 NotebookLM）

这是原流程最烧输出 token 的部分。**改为由 NotebookLM 用 `generate report --format custom` 逐模块生成长文并下载，主 LLM 不亲自写千字分析**。每个模块的 prompt 必须包含：四大师视角、正反两面论据、模块末尾追问、数据来源标注、★评分。

对每个模块执行一次：
```bash
notebooklm generate report "{模块 prompt，见下方各模块要点}" \
  --format custom -n <notebook_id> --language zh_Hans --json
# 解析 .task_id，轮询完成后下载
notebooklm artifact wait <task_id> -n <notebook_id> --timeout 1200
notebooklm download report ./step{N}-{模块名}.md -a <task_id> -n <notebook_id>
```

> 并行优化：六个模块彼此独立，可对 6 个 `generate report` 并行下发（注意 NotebookLM 限流，`--retry 3` 自带指数退避）。下载后主 LLM 逐份 `Read`，不一次性全部读入上下文——读一份、抽取要点、即可丢弃全文，只保留结论与数字。

各模块 prompt 要点（写入 `generate report` 的描述参数）：

#### 第二步：生意本质分析 — 段永平"对的生意"
- 用一句话定义这门生意的本质
- 收入结构拆解（表格）
- 5年盈利能力趋势（表格）
- 商业模式画布：一次性销售 vs 订阅/复购？硬件 vs 软件 vs 平台？
- 生态粘性/客户锁定强度
- 毛利率水平与同行对比，解释为什么高/低
- 经营杠杆分析
- **正反两面**：这门生意好在哪 / 哪些迹象说明它可能没看起来那么好
- **段永平式追问**：这门生意好在哪？如果只能用一句话描述，是什么？

#### 第三步：护城河评估 — 巴菲特"经济护城河"
逐一验证五类护城河（表格）：
| 护城河类型 | 验证方法 |
|-----------|---------|
| 品牌/定价权 | 是否能在不损失销量的情况下提价？ |
| 转换成本 | 客户迁移到竞品的成本有多高？ |
| 网络效应 | 用户越多产品越好吗？ |
| 规模效应 | 规模带来的成本优势有多大？ |
| 技术/专利壁垒 | 技术领先几年？能否被复制？ |
- 护城河趋势：过去5年变宽还是变窄？未来5年预判
- **正反两面**：每条护城河的反证（什么证据说明它没那么宽）
- **巴菲特式追问**：10年后这条护城河还在吗？什么能摧毁它？

#### 第四步：逆向思考与风险清单 — 芒格"反过来想"
- 列出"这家公司可能失败的所有路径"（表格：路径/概率/影响程度）
- 历史类比：找到历史上处于相似位置的公司，结局如何？
- 跨学科分析：用网络效应理论、技术采纳曲线、竞争博弈等模型交叉验证
- 偏误自查：叙事偏差、锚定效应、幸存者偏差
- 收集空方核心论点
- **芒格式追问**：我最可能在哪里犯错？聪明人为什么会不买/做空这家公司？

#### 第五步：管理层评估 — 段永平"对的人" + 巴菲特"管理层诚信"
- CEO/创始人关键决策复盘（表格：时间/决策/结果/评分）
- 资本配置能力：研发回报率、并购成功率、回购时机
- 股东利益一致性：管理层持股、薪酬结构、减持记录
- 组织能力：团队稳定性、关键人才风险
- 企业文化特征
- **段永平式追问**：如果CEO退休，这家公司还能保持竞争力吗？

#### 第六步：行业与文明趋势 — 李录"文明演进框架"
- 判断所在行业是否处于"文明级范式转移"
- 历史技术革命类比（蒸汽机/电力/互联网/AI）
- TAM增长曲线与天花板分析
- 公司在产业价值链中的位置
- 技术路线风险
- 客户/供应商集中度分析
- **李录式追问**：站在20年后回看，这家公司是"这个时代的标准石油"还是"昙花一现的3Com"？

#### 第七步：估值与安全边际 — 巴菲特"内在价值" + 段永平"对的价格"
**注意：此模块分两段——框架由 NotebookLM 写，精确数字由主 LLM 用工具算完回填。**

7A（NotebookLM 写框架，留空数字占位）：让 NotebookLM 生成估值框架，包含"当前市场定价表""反向DCF话术""三情景估值表""历史与同行估值对比"的结构，**数字位置用占位符 `{price}`/`{eps}`/... 标出，不要 NotebookLM 自己填数**。

7B（主 LLM 亲自计算回填，**禁止外包**）：
```bash
python3 tools/financial_rigor.py three-scenario \
  --price {股价} --eps {EPS} --shares {总股本亿} \
  --growth {乐观增速} {中性增速} {悲观增速} \
  --pe {乐观PE} {中性PE} {悲观PE} --years 3 --currency {币种}
```
把工具输出精确填入 7A 的占位符。**段永平式追问**：如果股市明天关闭5年，你愿意以这个价格持有吗？

### 数字对账步骤（六模块下载后必须执行，不可省略）

NotebookLM 在第二~七步长文里会自行冒数字（收入、份额、TAM、增速等），这些数字**未经程序验证**。主 LLM 逐份 `Read` 每份 `stepN-*.md` 时，必须做对账：

1. 抽出文中出现的每个关键数字
2. 与 1B 事实表 + 1C 工具验算结果比对
3. 不一致的，**以工具结果为准**，直接改正 `stepN-*.md` 中的数字并注明"已校验"
4. 记录对账差异到附录"数字对账记录"

> 若跳过此步，等于把"禁止心算"的纪律让渡给 NotebookLM，混合流程的严谨性优势即告丧失。

---

### 第八步：综合决策备忘录（主 LLM 亲自整合）

主 LLM `Read` 六份 `stepN-*.md`（已对账）+ 1C/7B 工具验算结果，写综合备忘录。此步输出量不大，留在主 LLM 合理。

汇总表格：

| 维度 | 结论 | 信心度 |
|------|------|--------|
| 生意质量（段永平） | | |
| 护城河（巴菲特） | | |
| 管理层（段永平+巴菲特） | | |
| 最大风险（芒格） | | |
| 文明趋势（李录） | | |
| 估值（巴菲特+段永平） | | |

最终决策表格：

| 策略 | 建议 |
|------|------|
| 空仓者 | |
| 持仓者 | |
| 卖出信号 | |
| 加仓信号 | |

四位大师的模拟点评（用引用格式）。

## 输出要求

1. 所有分析必须有数据支撑，附数据来源
2. 使用 Markdown 表格呈现关键数据
3. 每个模块末尾必须有对应大师的"追问"
4. 最终将完整报告写入 `~/[公司名]投资研究报告.md`（合并六份 `stepN-*.md` + 综合备忘录 + 对账与验算附录）
5. 结论要明确，不回避给出买入/观望/回避的建议
6. 估值部分必须给出具体的价格区间
7. **报告开头**必须包含"信息丰富度评级"（A/B/C）和"AI研究局限性声明"
8. **报告结尾**必须区分"AI分析置信度"与"投资确定性"——前者取决于资料量，后者取决于生意本质。明确告知读者：本报告的哪些结论基于充分数据，哪些基于有限信息的推理
9. 如果公司属于C级（信息稀缺），报告末尾必须列出"需要一手验证的问题清单"——建议读者通过田野调查、产品体验、供应链访谈等方式补充AI的盲区
10. 报告附录必须包含：1C 工具验算记录 + 数字对账记录 + 准出抽检记录

## 数据抽检（准出流程，主 LLM 编排，不可外包）

报告写入文件后，**必须**执行数据抽检，通过后方可发布：

**Step 1 — 提取抽检清单（15%随机抽样）：**
```bash
python3 tools/report_audit.py extract \
  --report <报告文件路径>
```
输出 JSON 模板，每项含 `fetched_value`（待填）。

**Step 2 — 取数核验：**
对清单中每个数据点，按 `skills/financial-data.md` 规范从可靠信源取数
（美股：macrotrends+stockanalysis；港股：aastocks+macrotrends；A股：东方财富+巨潮资讯），
填入 `fetched_value` / `fetched_source` / `fetched_value2` / `fetched_source2`。

**Step 3 — 输出判决：**
```bash
python3 tools/report_audit.py verdict \
  --results '<填好的JSON>' \
  --report <报告文件名>
```

- **【准出】**：所有抽检点偏差 ≤ 1% → 报告可发布
- **【打回】**：任意点偏差 > 1% → 修正对应数据后重新抽检，直到准出

| 环节 | 原流程 | 混合流程 |
